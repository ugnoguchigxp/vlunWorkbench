1. Conclusion

repositoryにはGitleaks、OSV、Trivy、Semgrep、SBOM、container scan、passive DAST、ZAP、 authorization matrix、business logic、dynamic、reproductionの実装がある。ただしcomponentの存在は、 profileが入力解決、preflight、実行、cancel、cleanup、coverage、reportを完遂できることを証明しない。 不足しているのは共通contract、lifecycle、qualification、truthful coverageである。

completeはsupport scope内の適用可能なrequired capabilityが実行され、input、policy、tool、evidence、 cleanupを追跡できることを指す。全脆弱性の自動検出、人手診断の代替、support boundary外の実装は意味しない。

1.1 Normative language

  • 「必須」「してはならない」はrelease gateであり、担当者の裁量で緩和しない。
  • 「既定」はproduction/CIのfail-closed値を指す。
  • 「evidence」はcurrent commit、input、policy、tool digestへ結び付いた保存済みartifactを指す。
  • 未決定事項はSection 6のdefault decisionを適用し、推測でscopeを広げない。

3. Fixed architecture contracts

3.1 Review decisions

  1. 本計画がcapability ID/requirementを所有し、Profile Catalogは同じschemaを再利用する。
  2. plan v2は既存scan_execution_plans.plan JSONへ保存し、v1をbackfillしない。
  3. 個別engineを再実装せず、adapterがchild run/resultをprofileへ結合する。
  4. ledgerはpure functionで導出し、finalization時にsnapshot保存する。
  5. plan v2、ledger、resource leaseを別work packageで導入する。

3.2 Capability model

secret_detection / source_sast / sca / iac_config / sbom
provenance_integrity / artifact_container / dynamic_tests / sanitizer_fuzz
passive_dast / browser_client / authentication_session / api_schema_contract
authorization_matrix / active_dast / business_logic / remediation_retest

requirement: required | required_if_applicable | advisory。 applicability: applicable | not_applicable | unknown。evidenceのないN/Aはunknown。

3.3 Execution plan v2

scanExecutionPlanSchema = discriminatedUnion("schemaVersion", [v1, v2])
v2: profile resolution + safety/approval + capabilityRequirements[]
    steps[]: inputBindingHash, policyHash, budget, cleanupRequirement
  • 現行shapeを意味変更なしでv1 schemaへrenameする。
  • writer flagはVULN_WORKBENCH_SCAN_EXECUTION_PLAN_V2一つ。api/app/env.tsでparse。
  • v1 preview後のv2切替はplan_changedで拒否し、暗黙再previewしない。
  • new kind: dynamic、active、authorization、business、reproduction、attestation。

3.4 Runner and normalized result

ProfileStepRunner: preflight / execute(AbortSignal) / cancel / cleanup
ProfileStepResult:
  stepId, kind, adapter, required
  execution: completed | failed | blocked | not_executed | cancelled
  applicability, coverageEffect, reasonCodes[], findingCount
  evidenceRefs[], artifactIds[], childRunRefs[]
  cleanupState: not_required | completed | failed | quarantined
  • GC-01では既存6 kindをregistryへ移すだけで結果意味を変えない。
  • exception textをreason codeとして保存せずcentral registryへmapする。
  • timeout/cancelもfinally cleanup。secret/cookie/passwordをplan/event/resultへ含めない。

3.5 Coverage ledger

buildCoverageLedger(requirements, planSteps, stepResults, receipts, derivedAt)
  -> CoverageLedgerV1(schemaVersion, planHash, entries, summary, ledgerHash)
  • pure functionはDB/filesystem/network/current timeを直接参照しない。
  • scan_runs.metadata.coverageLedgerへ保存し、reportにledger hashを固定する。
  • API/Web/report/zero-findingは同じsnapshotを読む。legacy runだけ既存projectionへfallback。
  • zero findingsとzero gapsを別状態にする。

3.6 Lifecycle, storage, compatibility

  • R1は元repo/.gitをmountせずfixed revision/manifestからsnapshotを作る。
  • R3はrun network/volume、stub external service、no real credential、reset invariantを要求する。
  • cleanup failureはquarantineしmanual cleanup actionを保存する。
  • reaper用scan_resource_leasesはrun/step/resource/provider/external ID/state/receipt/timestampsを持つ。 migration名はbun run db:generateで生成する。
  • flag offはv1 + v2-only schedule拒否。flag onはv2 writer + dual reader。
  • rollbackはnew v2 schedulingだけ停止し、saved v2/evidenceを読める。unknown future versionはfail-closed。

  • GC-04 user-managed command profileはlegacy/advancedとして残すがcommon profileから参照不可。

  • GC-06 existing RoE/target/reset validatorを迂回する第二validator禁止。
  • GC-07 reproduced → still_present。binding一致時だけ not_reproduced → fixed、差異はinconclusive。

6.2 Evidence manifest

artifacts/security-capability-gap/<slice>/evidence.v1.jsonに次を保存する。

schemaVersion / sliceId / workPackageIds[]
sourceRevision / sourceState
planHashes[] / ledgerHashes[] / tool/image/policy/input digests[]
testCommands[]: command, exitCode, time, logArtifactHash
fixtures[]: vulnerableOutcome, fixedOutcome
failureCases[]: expectedReason, actualReason, cleanupState
cleanupReceipts[] / limitations[] / review
  • dirty sourceはdiagnosticのみ。command文字列だけでなくexit code/log hashを要求。
  • review decision欠落をtechnical passで補わない。
  • runner missing、stale plan、timeout/cancel、malformed output、secret canary、cleanup failure、evidence-less N/A、zero finding + missing stepをnegative testする。

6.3 Default decisions for autonomous continuation

  1. security boundary、fail-closed policy、evidence immutabilityを優先。
  2. 既存schema/repository/runnerをadapterで再利用し第二実装を作らない。
  3. persisted contractはversion追加し既存field意味を変えない。
  4. applicabilityを証明できなければunknown。N/Aを推測しない。
  5. input/auth/RoE/lease/cleanup不足はdowngradeせずblocked/gap。
  6. 新dependencyより既存を優先し、security toolはtoolboxでdigest pin。
  7. query/reaper不要のstateはJSON/artifactへ保存しtableを増やさない。
  8. WP外refactor/renameをせず次候補へ記録。
  9. dirty fileを破棄、stash、上書きしない。対象と重なる場合はblocked。

schema外部互換性、production active access、secret handling、data deletion、claim基準変更が一意に決まらない時だけ maintainer判断を要求する。

6.4 Definition of complete

technicalCompletion = met iff:
  every required capability is covered
  required_if_applicable is resolved; applicable ones are covered
  no required step is failed/blocked/cancelled/not_executed
  every required cleanup is completed
  plan/ledger/input/policy/tool/evidence hashes are present

advisory gapはlimitationsに残し、completed_with_warningsにはできるがfull-coverage claimには使わない。 technical completionとPhase 56 human approvalは別fieldで、自動変換しない。

6.5 Risk and rollback

  • new kindはdefault hidden。qualification環境だけeligible。
  • R3は専用flow同等policy testまでmerge禁止。
  • rollbackはv2 schedulingだけ停止しhistorical dataを削除しない。
  • migration rollbackにdata deletionを使わずdual readerを先にdeploy。

8. Handoff, review closeout, and relationships

8.1 Handoff protocol

中断・完了時にledger statusと次を更新し、チャットだけを継続情報にしない。

Handoff
- Work package: GC-xx.y (status)
- Baseline/current commit:
- Goal completed:
- Files and symbols changed:
- Contract decisions made:
- Tests passed: command + exit code
- Tests not run/failed: command + reason
- Evidence paths and hashes:
- Unrelated working-tree changes preserved:
- Remaining blocker/risk:
- Exact next action: file, symbol, expected test
  • 「ほぼ完了」「あとはテスト」でなく未実行commandを列挙。
  • temporary resourceはlease ID/state/manual cleanupを残す。
  • 次担当はentry checkで現在状態を再確認。
