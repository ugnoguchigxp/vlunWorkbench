Scanner Hardening Archive Closeout Implementation Plan

Status: Proposed / standalone closeout plan

Parent plan: Backend Scanner Hardening and todolist Validation Plan

Planning baseline commit: 40e77d3

Planning baseline date: 2026-08-21

Owner: vulnWorkbench maintainers

Target: scanner hardeningのproduction実装を増やさず、変更範囲の固定、Definition of Doneの machine-readableな証明、verify:strictの終了記録を完了し、親計画を安全に spec/docs/.archived/へ移せる状態にする。

1. 結論

アーカイブまでの作業を次の3スライスへ限定し、順序を固定する。

  1. AR-01で現在の変更をscanner hardening対象、別計画対象、生成物に分類し、対象変更だけを review可能なimplementation commitへ固定する。
  2. AR-02で親計画の17個の完了条件をstable IDと実測証跡へ結び付ける。証拠がない条件は checkboxを更新せず、不足するtestまたはverifierを実装する。
  3. AR-03でclean checkout上の全gateを一つのrunnerから実行し、各commandの終了コードと evidence digestを保存する。全gate合格後だけ親計画をarchiveする。

3スライスを同時に完了扱いにしない。AR-01、AR-02、AR-03の順でhandoffし、前段の acceptanceが不合格なら後段を開始しない。

2. Scope

2.1 In scope

  • scanner hardening変更のpath inventoryと明示allowlist
  • 親計画の17個のDefinition of Doneに対するstable ID、evidence source、合否
  • 各scannerの実E2E、full profile repeatability、failure injectionの再検証
  • clean checkout上でのverify:strict実行と終了コードの保存
  • process、container、listener、target、production DB、production artifact rootの不変確認
  • closeout receiptのschema、runner、verifier、tests、package command
  • 親計画の完了記録、archive移動、spec index更新

2.2 Out of scope

  • scannerの追加、rule tuning、finding baselineの変更
  • scanner version、image、ruleset、vulnerability databaseの更新
  • UI表示、画面文言、routing、visual regressionの変更
  • todolist repositoryのsource、HEAD、working tree、runtime databaseの変更
  • professional capability claim、release tag、deploymentの更新
  • 親計画の未達条件を説明だけで達成扱いにすること

6.2 Scope contract

scanner-hardening-closeout-scope.v1.jsonは次を必須にする。

  • schemaVersion: 1
  • planningBaselineCommitの完全な40桁commit hash
  • allowedPathsの完全pathまたは末尾/**だけを許すprefix
  • excludedPathsと除外理由
  • generatedPathsと生成command
  • requiredPathsと、欠落した場合のstable reason code

..、absolute path、symlink escape、空prefix、repository root全体の /**は禁止する。unknown pathが1件でもあればexit 3で停止する。

6.3 Implementation sequence

  1. git diff --name-status 40e77d3と git ls-files --others --exclude-standardを取得する。
  2. renameは旧pathと新pathの両方を検査し、deleteもscope対象として扱う。
  3. 各pathを前節のclassへ割り当て、unknownを0件にする。
  4. scanner hardening対象だけをexplicit pathspecでstageする。
  5. git diff --cached --checkとscope checkerを実行する。
  6. staged diffをreviewし、production changeに対応testがない場合は停止する。
  7. implementation commitを作り、そのcommitからdetached clean worktreeを作る。
  8. 以降のAR-02とAR-03はclean worktreeだけで実行する。

自動化はgit reset、git checkout --、git clean、 git stashを実行してはならない。scope外変更を発見した場合はpath一覧を返して停止する。

6.4 Acceptance

  • baselineからimplementation commitまでのunknown pathが0件である。
  • implementation commitにweb/**変更が0件である。
  • required production pathごとに対応test pathがscope manifestへ登録されている。
  • clean worktreeのgit status --porcelain=v1が空である。
  • git diff --check 40e77d3..HEADがpassする。

8. AR-03 — Strict closeout receipt

8.1 Runner contract

scripts/scanner-hardening-closeout.tsはclean checkoutでだけ動作し、次を順番に 実行する。各commandはBun.spawnへ引数配列で渡し、stdout/stderrを画面へ転送しながら 個別fileへ保存する。pipelineや最後のconsole lineから合否を推測しない。

  1. full 40桁commit、clean status、scope contractを検証する。
  2. production DB、production artifact root、todolist HEAD/statusのbefore digestを採取する。
  3. bun run test:scanner-e2eを実行する。
  4. bun run scanner-e2e:failureとfailure verifierを実行する。
  5. bun run verify:strictを実行する。
  6. 全scanner evidence verifierをもう一度read-onlyで実行する。
  7. finallyで所有process、container、listener、temporary targetを停止・検査する。
  8. before/after digestを比較し、DoD predicateを評価する。
  9. 全条件合格時だけpromotable receiptを生成する。

SIGINTまたはSIGTERMを受けた場合は実行中childへ同じsignalを転送し、cleanupを完了してから non-zeroで終了する。中断runのpartial logはdiagnosticとして残せるが、closeout receiptへ昇格しない。

8.3 Log and evidence policy

  • run rootはartifacts/scanner-hardening-closeout/<run-id>/とする。
  • 既存run rootへは書かず、exclusive createを使う。
  • raw log、SQLite、scanner artifactはGitへ追加しない。
  • receiptにはrelative path、SHA-256、size、exit codeだけを保存する。
  • absolute path、secret、environment dump、raw finding bodyをreceiptへ保存しない。
  • promotion後のtracked receiptを再生成または上書きしない。

12. Stop conditions

  • scope外path、特にweb/**がimplementation commitへ混入した。
  • DoDをconsole text、手動記憶、自己申告のassertion IDだけでpassにした。
  • TS、FI、SH-DODのrequired IDが一つでも欠落した。
  • scanner E2Eまたはstrict gateをskipしてreceiptを生成した。
  • target、production DB、production artifact rootが変更された。
  • owned process、container、listenerが一つでも残った。
  • 既存evidence、receipt、raw artifactを上書きした。
  • todolist codeをhost processとして起動した。
  • scannerが実行中にbinary、rules、template、databaseをdownloadした。
  • 失敗結果をcompleted、0 finding、warningだけへ変換した。

13. Definition of Done

  • AR-01のscope checkerがclean checkoutでpassする。
  • scanner hardening対象のimplementation commitが存在する。
  • scope外変更がscanner hardening commitに含まれない。
  • SH-DOD-01からSH-DOD-17が全て実測証跡でpassする。
  • 全12 individual scanner E2E caseがpassする。
  • FI-01からFI-11が全てfail closedする。
  • full profile 2 runのrepeatability verifierがpassする。
  • verify:strictのexit 0がreceiptへ保存される。
  • closeout receipt verifierがpassする。
  • cleanup、target、production dataの全predicateがpassする。
  • 親計画の完了記録がreceiptと一致する。
  • 親計画と本計画をarchiveへ移したdocs-only commitがpassする。

上記12項目が全てpassした時点でのみ、親計画と本計画をarchive可能と判定する。未完了項目を 別計画へ移管する場合は、移管先のactive plan、owner、acceptance、開始条件をreceiptへ記録する。 単なる「後で対応」は移管として認めない。
