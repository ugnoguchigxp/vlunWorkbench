# 検出能力の実測と再現

`bun run verify:capability:linux` はDockerを使い、Linux上のクリーンな現コミットで全ベンチマークを実行する。OSV、Semgrep、Juice Shopのイメージはダイジェストで固定し、測定コンテナの外部ネットワークを無効にする。準備時だけ、固定されたコーパス・イメージ・データを取得する。Docker Desktopでも実行できる。

```sh
# OSV/Trivyのデータを実際に更新し、再現用バンドルも保持する。
bun run scanner-data:refresh-lock .cache/scanner-data/current
# 更新したマニフェストや実装をレビュー・コミットした後に実行する。
bun run verify:capability:linux
```

Linuxホストでは、`VULN_WORKBENCH_OWASP_SEMGREP_IMAGE`、`VULN_WORKBENCH_OSV_FIXTURE_IMAGE`、`VULN_WORKBENCH_OSV_FIXTURE_DB`を設定して`bun run verify:capability:full`を直接実行できる。CIのverifyワークフローが具体例になる。既存のデータベースを指定する必要はなく、測定ごとに隔離したSQLiteデータベースを作成する。

結果は`.artifacts/capability/<実行ID>/report.json`に保存する。同じディレクトリに測定結果、Juice Shopの要求・応答の証跡、保存済みベンチマークのSQLiteデータベースを保管する。レポートにはコミット、ソースツリー、スキャナー、マニフェスト、各成果物のハッシュ、実行したコマンドと終了コードを含む。後の測定によって過去の実行ディレクトリは上書きされない。

全件の実行と能力基準の充足を確認し、保存済みOWASP実行IDを照合した場合にだけ`passed`となる。未実行、データ期限切れ、誤った入力ハッシュ、未完了の後片付け、変更中のチェックアウトは合格にしない。`benchmark:all`も未完了の場合は終了コード1を返す。

測定の範囲は次のとおり。

| 測定 | 対象と判定 |
| --- | --- |
| OWASP Java | 固定コーパスに対する自社SemgrepルールとJava後処理の再現率・適合率・誤検知率。カテゴリ別の最低基準も維持する。 |
| Java独立フィクスチャ | OWASPと別の18正例・10負例を固定Semgrepと本番後処理で実行する。引数・出現位置・別名・コレクション変更・リクエストラッパー・HTML出力先を検証する。未実行や検出不一致を全体の不合格にする。 |
| Juice Shop | 固定イメージ上の20シナリオと修正済み対照。実行、検出、復元、外部通信を照合する。 |
| OSV | 8エコシステム・9形式の脆弱版と修正版を実DBでスキャンする。DBのハッシュとネットワーク遮断を必須にする。 |
| 業務ロジック | 8組の状態を持つ自社HTTPフィクスチャを実行し、観測した違反と復元結果を採点する。テストが通ったことから検出数を推定しない。 |
| エンドポイント抽出 | 11フレームワークの正例と負例を抽出器に入力する。 |
| 標準DAST | 自社HTTPアプリで探索・検出・証跡・要求数・失敗時の判定を検証する。 |

DBの有効期限は既存ポリシーの168時間を維持する。`osv-fixtures:prepare`はロックと一致する既存スナップショットを再利用する。配布元の`all.zip`が更新されてハッシュが一致しなくなった場合は、保存したバンドルを復元するか、上記の明示的な更新を行う。日時だけを書き換えて期限を延長しない。CIキャッシュが消えた場合に備え、正式な測定に使ったデータバンドルも保持する。

合格はこの表の測定対象に対する主張であり、任意の業務要件、任意のフレームワーク、動的な設定、反射、実行時の組み合わせを網羅するものではない。特に自社の業務ロジックフィクスチャの成功は、未知のアプリケーションから業務ルールを自動推定できるという意味ではない。

## Javaの警告を取り除く条件

Java後処理は構文木で警告の開始・終了位置を実際の引数に結び付け、そこへ到達する値を評価する。変数名やベンチマークのケース名を安全判定の根拠にしない。分岐、整数演算、コレクション・配列・StringBuilderの書き換え、ソースを確認できるメソッドを扱う。継承やオーバーロードで呼び先を確定できない場合、変更可能な値が未知の処理に渡る場合、構文・探索・評価の上限を超える場合は警告を残す。

設定から選択する実装は、設定値、選択したクラス、例外時の代替実装をソースで照合する。ダイジェスト名もJava Propertiesのエスケープ・継続行・重複キーの規則で読む。未解決の設定を安全とはみなさない。抑制した警告には対象ソースと、依存ソース・設定を含めた判定入力のハッシュを記録する。

HTMLエンコードをJavaScript、CSS、URLなどの出力先に流用する明示的なケースを別ルールで検出する。後処理がHTML本文への出力を安全とみなすには、Content-Typeと直前の出力内容も確認する。未知の処理へresponseやwriterを渡した後は本文の位置を確定できない。テンプレート、実行時のHTML構築、クラスパス全体や任意の反射の完全解析は対象外である。

`test:detection-effectiveness`で後処理への反例と判定入力の改変を検証し、`test:semgrep:java-holdouts`で検出から後処理までを通した結果を検証する。後者の結果とスキャナーの生出力も正式測定の実行ディレクトリに保存する。再現率だけを上げるために誤検知率の基準を緩和しない。

StringBuilderのappend・insert・setCharAtも入力の伝播対象に含める。配列長が分岐によって異なる場合は全要素の安全性だけを保持し、長さを確定したものとして後の変更を評価しない。printfの未確定書式や文字コードからHTMLを構成できる変換を本文の安全性証明に使わない。
