1. Purpose

vulnWorkbenchのontology handoffとSemanticaの設計を比較して得た6つの候補を、 後から個別に深掘りできる計画雛形として分離する。各文書は単独で、目的、現状根拠、 scope、実装候補、検証条件、未決事項を確認できるようにする。

Semanticaは設計上の手がかりであり、採用済みdependencyではない。調査基準は Semantica commit cce5ea1、公式の Ontology、 Provenance、 Reasoning documentationとする。

2. Fixed Boundaries

  • vulnWorkbenchは観測されたstructure / security / CI factとprovenanceを公開する。
  • NightWorkersはtask / run scoped projection、限定推論、executionを所有する。
  • canonical meaning、claim approval、conflict resolutionは将来のOntology Coreの責務候補である。
  • semantic result、embedding、LLM interpretationをobserved factへ自動昇格しない。
  • RDF化、triple store導入、Semantica runtime依存、schema変更は各計画のGO判断まで行わない。
  • 既存ロードマップのStage entry gateとrollout decisionが、この雛形群より優先する。

4. Suggested Working Order

  1. competency questionを少数固定し、現行baselineを測る。
  2. semantic handoff validationとclaim provenanceをP0 discoveryとして並行検討する。
  3. security vocabulary alignmentで外部識別子と同値性の強さを固定する。
  4. contract version / diffでproducer-consumer migrationを固定する。
  5. 最後にNightWorkersで限定rule inferenceを試験する。

5. Shared Decision Gate

各計画をactive planへ昇格する前に、最低限次を記録する。

  • owner、対象Stage、entry / exit gate、対象外、rollback条件
  • 現行fixtureでのbaselineと、改善を判定するmetric
  • vulnWorkbench / target repository / Ontology Core / NightWorkersの責務分担
  • wire compatibility、migration順、失敗時のfail-safe挙動
  • Semanticaから借りる設計原則と、借りないruntime機能
